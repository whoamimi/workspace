# Security Policy

## Supported Versions

The following versions currently receive security updates.

| Version | Supported          |
| ------- | ------------------ |
| 5.1.x   | :white_check_mark: |
| 5.0.x   | :x:                |
| 4.0.x   | :white_check_mark: |
| < 4.0   | :x:                |

## Reporting a Vulnerability

Please do not report security vulnerabilities through public GitHub issues.

### Where to report

- **Preferred:** Use GitHub's private vulnerability reporting.
  Go to the [Security tab](https://github.com/whoamimi/workspace/security/advisories/new) and select **Report a vulnerability**.
- **Alternative:** Email `your-email@example.com` with the subject line "Security: <short summary>".

### What to include

- A description of the vulnerability and its potential impact
- Steps to reproduce, or a proof of concept
- The affected version(s)
- Any suggested fix, if you have one

### What to expect

- **Acknowledgement:** within 3 business days of your report.
- **Status updates:** at least every 7 days until the issue is resolved.
- **If accepted:** we will confirm the issue, develop a fix, and release a patch for all supported versions. We will credit you in the release notes unless you prefer to stay anonymous.
- **If declined:** we will explain why, for example if the behaviour is intended or falls outside the supported versions. You are welcome to reply with additional information.

### Disclosure

We ask that you keep the details private until a fix is released. We aim to publish fixes within 90 days of the initial report, and we will coordinate the disclosure date with you.

Thank you for helping keep this project and its users safe.
